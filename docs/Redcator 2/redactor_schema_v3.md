# Redactor — Database Schema
## Version 3.1 — Cowork Architecture

---

## Design Principles

1. Client-scoped redaction — entity mappings persist at client level across all sessions
2. Redaction is the gateway — unredacted content never enters the workspace or database (except entity_mappings which store originals for re-identification)
3. Re-identification at display only — stored content always redacted, substitution applied at render time
4. Cowork boundary — Cowork never accesses the database directly. All Cowork interactions go through MCP tools → HTTP server → app logic → database
5. AI-transport-agnostic — schema works identically whether AI content arrives from Cowork via MCP or from direct API calls

**Processing status flow — Recorded sessions:**
```
active                  Recording in progress. Live analysis running in Cowork.
  → ended               Recording stopped. Chunks in workspace. Live analysis skill exits.
  → pending_redaction    Therapist has not yet reviewed redaction.
  → redacted             Therapist reviewed and confirmed entity mappings.
                         Chunks rewritten with corrected redaction.
                         redaction_confirmed.json written to session folder.
                         Session is now eligible for /process-sessions.
  → processed            Notes and/or feedback generated by Cowork.
                         transcript_expires_at set to now + 14 days.
```

**Processing status flow — Rough notes / uploaded documents:**
```
pending_redaction       Document uploaded, redaction scan complete, awaiting review.
  → redacted            Therapist confirmed. Unredacted original deleted.
  → processed           Notes generated.
```

**What the app shows for each status:**
| Status | App UI indicator | Action available |
|--------|-----------------|------------------|
| active | "Recording" (green pulse) | Stop recording |
| ended | "Awaiting review" (amber) | Open redaction review |
| pending_redaction | "Awaiting review" (amber) | Open redaction review |
| redacted | "Ready to process" (blue) | Directs user to Cowork `/process-sessions` |
| processed | "Complete" (green check) | View notes, feedback, export |

**What Cowork sees for each status:**
The `/process-sessions` skill uses workspace markers to determine status:
- `session_complete.json` exists but no `redaction_confirmed.json` → skip (not ready)
- `redaction_confirmed.json` exists but no `clinical_notes.json` → **process this session**
- `clinical_notes.json` exists → already done, skip

### entity_mappings
Source of truth for original → replacement code. Supports client-level persistence across sessions. This is the persistent redaction library.

| Column | Type | Constraints | Notes |
|--------|------|-------------|-------|
| id | TEXT | PRIMARY KEY | UUID |
| client_id | TEXT | NOT NULL, FK → clients.id | |
| session_id | TEXT | NULLABLE, FK → sessions.id | NULL for client-scoped mappings |
| document_id | TEXT | NULLABLE, FK → source_documents.id | NULL for session mappings |
| persistence_scope | TEXT | NOT NULL | session / document / client |
| original_text_normalized | TEXT | NOT NULL | Lowercase. First-write-wins key |
| original_text | TEXT | NOT NULL | Cased original |
| replacement_code | TEXT | NOT NULL | e.g. [PERSON_A] |
| entity_type | TEXT | NOT NULL | Same enum as entities.type |
| created_at | TEXT | NOT NULL | ISO 8601 |

**Unique constraint:** (client_id, persistence_scope, original_text_normalized)

**Lifecycle:**
- When a new client is created, the app auto-creates two `persistence_scope = 'client'` mappings: client name → `[CLIENT_A]` (with variants) and therapist name → `[THERAPIST_A]` (with variants, copied from `clinician` table set at onboarding). These are `source = 'system'` and cannot be excluded or deleted.
- **Session start:** Database → file. Client-scoped mappings are exported to `Private/{initials}/entity_map.json` and loaded into in-memory `EntityMapping`.
- **During session:** New entities detected get `persistence_scope = 'session'` and are added to memory + working file.
- **Post-session review:** Therapist reviews new entities in the app. Confirmed entities are promoted: copied from `persistence_scope = 'session'` to `persistence_scope = 'client'` (session record preserved).
- **Session end:** Promoted client-scoped mappings are written to both this table and `entity_map.json`.
- **If file and database diverge:** Database wins. File is regenerated from database on next session start.
- Subsequent person entities are assigned codes starting from `PERSON_B` (since `CLIENT_A` is pre-seeded)

## What Is NOT in the Database

**In workspace as files (path stored in documents table):**
session notes, client notes, feedback narratives, external reports, client correspondence, formal reports, rolling session summaries, clinical background summaries

**In workspace as transient files (not indexed):**
session_state.json, chunk files, .server_token, session_complete.json

**In Private/ folder (never in database file references):**
entity_map.json — the working copy of the redaction library. Synced to/from entity_mappings table.

**Memory only — never persisted:**
raw audio beyond chunk file references, live dashboard metrics during session

**Temp directory — invisible to Cowork:**
unredacted transcript, uploaded documents before redaction confirmed

## Key Relationship Map

```
clinician (1)
clients (many)
  ├── sessions
  │     ├── audio_chunks (temp, deleted on session end)
  │     ├── transcript_segments (expires 2 weeks)
  │     ├── documents (session-level outputs)
  │     └── feedback_scores
  ├── entity_mappings (client-scoped, persistent redaction library)
  ├── entities (client-scoped, persistent)
  ├── redacted_persons (client-scoped)
  ├── documents (client-level, no session)
  └── source_documents (uploaded material)

report_templates (app-level, standalone)
practitioner_metrics (clinician-level, no client FK)
```

## Cascade Deletion on Client Discharge

When a client is discharged + 30 days:

```
DELETE FROM feedback_scores WHERE client_id = ?
DELETE FROM documents WHERE client_id = ?
DELETE FROM transcript_segments WHERE session_id IN (SELECT id FROM sessions WHERE client_id = ?)
DELETE FROM audio_chunks WHERE session_id IN (SELECT id FROM sessions WHERE client_id = ?)
DELETE FROM entity_positions WHERE entity_id IN (SELECT id FROM entities WHERE client_id = ?)
DELETE FROM entities WHERE client_id = ?
DELETE FROM entity_mappings WHERE client_id = ?
DELETE FROM redacted_persons WHERE client_id = ?
DELETE FROM source_documents WHERE client_id = ?
DELETE FROM sessions WHERE client_id = ?
DELETE FROM clients WHERE id = ?

-- File system:
rm -rf Workspace/Sessions/{initials}/
rm -rf Workspace/Private/{initials}/

-- practitioner_metrics NOT deleted (no client FK)
```
