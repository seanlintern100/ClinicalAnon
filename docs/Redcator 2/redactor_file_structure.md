# Redactor — File Structure Map
## Version 2.0

---

## Overview

Three distinct storage areas exist on the clinician's device:

**SQLCipher Database** — Encrypted structured data. The app's internal system of record.
**Workspace** — File-based interface between the app and Cowork. Contains redacted content only. Subdivided into Sessions (Cowork-accessible), Private (app-only), and CoWork Files (Cowork working folder).
**Temp Directory** — Unencrypted working area for unredacted material. Never visible to Cowork. All contents short-lived.

## Database: redactor.db

SQLCipher encrypted database. Encryption key stored in macOS Keychain. Contains all structured data — client records, sessions, entities, mappings, feedback scores, document index, templates.

Cowork never accesses the database. All Cowork interactions go through MCP tools → HTTP server → app logic → database.

See `redactor_schema_v3.md` for full table definitions.

---

## Workspace

### Sessions/ — MCP Root

This is the `REDACTOR_EXPORT_ROOT` configured in the MCP server. Cowork accesses everything here via MCP tools. All content is redacted — substitution tokens only, never real names.

#### index.json — Root Index

Lives at `Sessions/index.json`. Written and maintained entirely by the app. Cowork reads this at the start of any cross-client or caseload-level task to understand the full client landscape.

```json
{
  "generated_at": "2026-03-20T09:00:00Z",
  "clinician": {
    "name": "[THERAPIST_A]",
    "title": "Clinical Psychologist"
  },
  "clients": [
    {
      "initials": "JB",
      "status": "active",
      "default_session_type": "therapy",
      "onboarding_date": "2025-06-01",
      "session_count": 12,
      "last_session_date": "2026-03-15",
      "notes_generated_count": 11,
      "feedback_generated_count": 10,
      "has_rolling_summary": true
    }
  ]
}
```

**What it excludes:** No real names, no clinical content, no DOB. Aggregate metadata only. Safe at caseload level.

**When it is updated by the app:**
- A new client is created (new entry added)
- A client is discharged (entry removed)
- A session completes (session_count, last_session_date updated)
- Notes or feedback are generated (counts updated)

---

#### [INITIALS]/ — Client Folder

One folder per client, named by initials (e.g., `JB`). Initials are assigned by the app when a client is created and stored in the database. For collisions, a numeric suffix is added (`JB2`).

**client_profile.json** — Written by the app when a client is created or updated. Cowork reads this for context at the start of any client-scoped task.

```json
{
  "initials": "JB",
  "preferred_name": "[CLIENT_A_FIRST]",
  "pronouns": "he/him",
  "default_session_type": "therapy",
  "default_session_type_desc": null,
  "default_duration_minutes": 50,
  "session_count": 12,
  "last_session_date": "2026-03-15",
  "onboarding_date": "2025-06-01",
  "status": "active"
}
```

Note: `preferred_name` uses the client's redaction code, not their real name. The app applies entity substitution when displaying this in the UI.

**When it is updated by the app:**
- Client record is created or edited (name, pronouns, session defaults)
- A session completes (session_count, last_session_date)

---

**client_index.json** — Written by the app. The primary navigation file for Cowork when working on a specific client. Lists all sessions and generated documents with metadata and one-sentence summaries.

```json
{
  "initials": "JB",
  "generated_at": "2026-03-20T09:00:00Z",
  "sessions": [
    {
      "session_id": "JB_2026-03-20_0937",
      "session_date": "2026-03-20",
      "session_type": "therapy",
      "folder": "2026-03-20_0937",
      "has_notes": true,
      "has_feedback": true,
      "chunk_count": 15
    },
    {
      "session_id": "JB_2026-03-15_1400",
      "session_date": "2026-03-15",
      "session_type": "therapy",
      "folder": "2026-03-15_1400",
      "has_notes": true,
      "has_feedback": true,
      "chunk_count": 12
    }
  ],
  "documents": [
    {
      "document_type": "session_note",
      "session_id": "JB_2026-03-20_0937",
      "session_date": "2026-03-20",
      "file_path": "2026-03-20_0937/clinical_notes.json",
      "summary": "Session focused on workplace anxiety and avoidance patterns; [CLIENT_A_FIRST] reported progress with exposure hierarchy."
    },
    {
      "document_type": "feedback_narrative",
      "session_id": "JB_2026-03-20_0937",
      "session_date": "2026-03-20",
      "file_path": "2026-03-20_0937/feedback.json",
      "summary": "Strong listening quality and empathy. Watch point on goal alignment — session drifted from stated agenda."
    },
    {
      "document_type": "rolling_session_summary",
      "session_id": null,
      "session_date": null,
      "file_path": "rolling_summary.md",
      "summary": "Ongoing therapy addressing workplace anxiety, avoidance, and self-worth themes across 12 sessions."
    }
  ]
}
```

**What it excludes:** No real names in summaries — substitution tokens only. No clinical detail beyond one-sentence summaries.

**When it is updated by the app:**
- A new session is created (session entry added)
- Session completes (chunk_count, has_notes, has_feedback updated)
- The app ingests a new document from Cowork (document entry added with summary)
- A document is deleted (entry removed)

**Summaries:** The app generates one-sentence summaries when ingesting Cowork-generated documents. For the rolling summary, the summary field is a static description. For session notes and feedback, the app extracts a summary from the content on ingestion.

---

**rolling_summary.md** — Written by Cowork after each session via `write_rolling_summary` MCP tool. Contains a running clinical summary in redacted form. The app creates an empty file when the client folder is first created. Cowork overwrites the entire file on each update (not append). If it grows beyond approximately 2000 words, Cowork should summarise it as part of the update. The app displays this with entity substitution.

#### [YYYY-MM-DD_HHMM]/ — Session Folder

One folder per recorded session. Named by session date and time.

**session_info.json** — Written by the app when recording starts.
```json
{
  "session_id": "JB_2026-03-20_0937",
  "initials": "JB",
  "session_type": "therapy",
  "session_date": "2026-03-20",
  "session_goals": "Explore workplace anxiety triggers",
  "duration_minutes": 50,
  "speakers": 2
}
```

**chunk_NNN.json** — Written by the app as transcript segments are redacted. One file per chunk. Contains redacted text with speaker labels and timestamps.
```json
{
  "chunk_index": 1,
  "session_id": "JB_2026-03-20_0937",
  "timestamp_start": "00:00:00",
  "timestamp_end": "00:02:15",
  "segments": [
    {
      "speaker": "therapist",
      "text": "How have things been since we last met?",
      "timestamp": "00:00:00",
      "timestamp_end": "00:00:03"
    },
    {
      "speaker": "client",
      "text": "[CLIENT_A_FIRST] mentioned that [PERSON_B] at [ORG_A] had...",
      "timestamp": "00:00:04",
      "timestamp_end": "00:02:15"
    }
  ]
}
```

**session_state.json** — Written by Cowork during live session. Contains analysis metrics for the dashboard. Transient — deleted after session is ingested.

**session_complete.json** — Written by the app when recording stops. Signals to Cowork's `/live-session` polling loop that the session has ended and the skill should exit.
```json
{
  "completed_at": "2026-03-20T10:30:00Z",
  "total_chunks": 15,
  "recording_duration_seconds": 2940
}
```

**redaction_confirmed.json** — Written by the app after the therapist completes redaction review. This is the trigger for `/process-sessions` — Cowork will only generate notes/feedback for sessions that have this marker. At this point the chunk files have been rewritten with corrected entity codes.
```json
{
  "confirmed_at": "2026-03-20T12:00:00Z",
  "entities_confirmed": 8,
  "entities_corrected": 2,
  "entities_added": 1,
  "entities_promoted_to_persistent": 3
}
```

**clinical_notes.json** — Written by Cowork via `write_clinical_notes` MCP tool during `/process-sessions`. Uses corrected redaction from reviewed chunks. Permanent. See schema in Cowork Integration Spec.

**feedback.json** — Written by Cowork via `write_feedback` MCP tool during `/process-sessions`. Uses corrected redaction. Permanent. See schema in Cowork Integration Spec.

**.server_token** — Written by the app when a session is activated. Contains `{ token, port }` for MCP auth. Transient — deleted after session is fully processed.

#### reports/ — Client-Level Reports

Reports are client-level, not session-level — they typically draw from multiple sessions. Stored at `Sessions/{initials}/reports/`.

**Internal reports** (generated by Cowork via `/report` skill):
- `formal_report_{date}.json` — ACC assessments, clinical reviews, progress reports
- Written by Cowork via `write_report` MCP tool
- App ingests into `documents` table with `document_type = 'formal_report'`

**report_request.json** — Written by the app when the clinician selects a report type and source documents. Cowork reads this when the `/report` skill is invoked. Retained after processing.

#### external/ — Uploaded Background Documents

Background documents uploaded by the clinician (referral letters, external assessments, prior reports). These are uploaded via the app, redacted, and stored here for Cowork to access when generating reports or other outputs.

- Uploaded in the app → redacted via the standard pipeline → therapist confirms → stored here
- Cowork can read these via `get_document` MCP tool
- App ingests into `documents` table with `document_type = 'external_report'` or `'client_correspondence'`

### Session Status Markers (how Cowork determines session state)

Cowork uses the presence of marker files to determine what to do with a session:

| Marker files present | Session state | Cowork action |
|---------------------|---------------|---------------|
| None | Active or not started | `/live-session` can start it |
| `session_complete.json` only | Ended, awaiting redaction review | Skip — therapist must review in app first |
| `session_complete.json` + `redaction_confirmed.json` | Reviewed, ready to process | `/process-sessions` picks it up |
| `session_complete.json` + `redaction_confirmed.json` + `clinical_notes.json` | Fully processed | Skip — already done |

### Private/ — App Only

Entity maps with real names. No MCP tool has access to this directory. No path to this directory is configured in the MCP server.

**entity_map.json** — The persistent redaction library for a client. Maps redaction codes to real names. Updated after each session when new entities are confirmed.

```json
{
  "version": "1",
  "client_initials": "JB",
  "updated_at": "2026-03-20T10:35:00Z",
  "mappings": {
    "CLIENT_A": "James Brown",
    "CLIENT_A_FIRST": "James",
    "CLIENT_A_LAST": "Brown",
    "PERSON_B": "Sarah Wilson",
    "PERSON_B_FIRST": "Sarah",
    "ORG_A": "Wellington Hospital",
    "LOCATION_A": "Wellington"
  }
}
```

The entity map file is the working copy used during sessions. The database `entity_mappings` table is the authoritative store. Sync direction: on session start, database exports client-scoped mappings to this file. During session, new detections are written to this file as a working copy. On session end, confirmed new mappings are written back to the database and this file is updated. If file and database diverge, database wins — the file is regenerated on next session start.

---

### CoWork Files/ — Cowork Working Folder

The user opens this folder as their working directory in Cowork. It contains:

**CLAUDE.md** — Global instructions directing Cowork to use available skills. Written by the app on launch.

**.claude/skills/** — Auto-generated SKILL.md files for each workflow. Written by the app on launch via `SessionExportService`. Cowork discovers these as slash commands.

---

## Temp Directory

Completely separate from the workspace. No MCP tool has access. No path is configured anywhere Cowork can reach.

**[session-uuid]-raw-transcript.txt** — Full unredacted transcript assembled after recording ends. Held during post-session redaction review. Deleted on redaction confirmation or abandonment.

**[session-uuid]-upload-[doc-uuid].txt** — Uploaded documents before redaction confirmed. Same lifecycle.
